# L8 Deliverables — Independent Application Discovery & Budget-Efficient Detection

Scope statement first, so nothing else in this document can be
misread: every number below is measured on synthetic loopback
fixture applications running inside this repository's own
benchmark harness. They characterize the engine against
independently implemented test applications; they support no claim
about real-world systems of any kind.

## 1. Reproducible L7 results (starting point)

Recorded in `docs/L8_REPRODUCTION.md`: archive SHA-256 verified
against three independent references, manifest digests audited (two
bookkeeping defects found and corrected, neither touching
evaluation output), full gate reproduced (4477 passed, coverage
62.07%, lint and security clean, both authority gates OK), and the
144-run A/B/C/D matrix re-run with every field outside wall-clock
seconds byte-equal to the committed L7 artifact.

## 2. Independently implemented applications (§2 evidence)

The L8 appsuite (`src/webpent/appsuite/`) holds four applications,
each with four variants (defective, secured, ambiguous,
multi_observation): docvault (grant-matrix document ownership,
IDENTITY_BOUNDARY), market (catalog-plus-quote pricing,
PRICE_INTEGRITY), ticketflow (edge-table workflow transitions,
WORKFLOW_ORDER), slots (hold-ledger idempotent mutation,
deliberately outside every engine-tuned family). Independence is
mechanical, not asserted:

- `tests/appsuite/test_isolation.py` (9 checks): the external
  vocabulary of every appsuite module is disjoint from both prior
  corpora (the L5/L6 canonical wire vocabulary and the L7 labsuite
  wordlist); no appsuite module imports fixture, labsuite or
  detector implementation code; the detector package never
  references the appsuite. The name-disjointness bound is honest
  about its own limit: renaming routes and ids alone would NOT
  establish independence, so the binding evidence is the absence of
  shared implementation logic, checked by import and text, plus
  four hand-written applications with distinct data models (grant
  matrix, quote ledger, workflow edge table, hold ledger).
- Ground truth is declared in `appsuite/groundtruth.py` from each
  app's enforcement matrix; slots' idempotent_mutation family maps
  to no engine family and was never used to tune anything (§2's
  untuned invariant family).
- Variant shapes include defective, secured-lookalike (defect
  declared but enforced), ambiguous (a behavior that reads like a
  defect and is not), and multi-observation (defect scoped to one
  collection/bucket).

True independence limitations, stated plainly: the applications
were authored in the same repository by the same author as the
engine; the variant taxonomy itself could encode assumptions the
engine was tuned toward; and the shared harness (SuiteTarget,
index contract) is common infrastructure, deliberately structural
rather than name-based, but common nonetheless.

## 3. Discovery efficiency results (§3)

Raw per-instance records, discovery curves and aggregates are in
`docs/l8_discovery_dev.json` (160 runs, DEV block, generated
BEFORE held-out was touched) and `docs/l8_discovery_heldout.json`
(160 runs, measured once after the DEV analysis was frozen). Each
run record carries requests (engine observations: one per HTTP
exchange the engine issued and recorded), http_requests (every
request the serving stack answered, including index fetches),
seconds, unique TP/FP/FN (deduplicated: one defect = one finding),
raw hypothesis-level confirmations, requests-per-unique-TP,
hypotheses generated by family, status and outcome tallies,
executed/duplicate experiment counts, terminal reason, budget
binding, rounds used, and the sealed replay digest. Units are
declared in each JSON's `metric_units` block.

Budget-matched unique-TP/FP/FN (summed over 8 instances per block):

DEV block (tuning; the §5 fix landed between generations):

| budget | adaptive | indep-fixed | adapt-no-sel | obs-baseline |
|---|---|---|---|---|
| 2  | 3/0/1 | 0/0/4 | 3/0/1 | 2/0/2 |
| 4  | 4/0/0 | 2/0/2 | 4/0/0 | 2/0/2 |
| 8  | 4/1/0 | 2/0/2 | 4/1/0 | 2/0/2 |
| 16 | 4/1/0 | 2/0/2 | 4/1/0 | 2/0/2 |
| 32 | 4/1/0 | 2/0/2 | 4/1/0 | 2/0/2 |

Held-out block (no engine change after measurement):

| budget | adaptive | indep-fixed | adapt-no-sel | obs-baseline |
|---|---|---|---|---|
| 2, 4, 8, 16, 32 (identical) | 2/0/4 | 2/0/4 | 2/0/4 | 2/0/4 |

Interpretation, at the largest budget: on DEV the adaptive
strategies reach recall 1.0 with one designed false positive (the
documented dv-103 guest read) at 57.8 requests/TP, versus recall
0.5 for both fixed baselines. On held-out all four strategies are
identical (2/0/4): WORKFLOW_ORDER is found immediately by
everyone, the WORKFLOW_IDENTITY defects by no one (§4 below), and
two FN per run are slots' deliberately untuned idempotent_mutation
family, which no strategy can find by design. There is no adaptive
advantage on held-out; the observation baseline matches at lower
cost. That is the measured result and is reported as such.

## 4. Failure analysis and the smallest improvement (§5)

`docs/L8_FAILURE_ANALYSIS.md`: the generation-1 DEV measurement
missed both multi-observation defects because probe generators
picked a single resource outside the defective scope; the fix is
one constant (`RESOURCE_PROBES_PER_OPERATION = 3`) plus per-resource
probe repetition in two generator loops, proven red-first by two
tests that failed before and pass after; the benchmark correction
(discovery-v2) it forced; and the held-out gaps (the
WORKFLOW_IDENTITY false-negative mechanism on ticketflow,
diagnosed but deliberately not fixed because held-out outcomes can
no longer influence tuning).

## 5. Metric-inflation controls (§4)

Unique-scoring (`score_unique` in the matrix script) counts each
defect once regardless of repeats, puts FPs in every denominator,
never counts inconclusive as confirmed, and carries
duplicate-experiment counts. Evidence is sealed per run
(`seal`) and replays against the recorded requests. The preserved
disciplines are unchanged from L7: ActionAuthority/ActionExecutor,
G-02, scope checks, CausalGuard, ProofBundle, idempotency. The L7
labsuite evaluator gained the same dedup rule (first confirmation
per family counts, repeats land in `duplicate_confirmations`).

## 8. Evidence statement

What is established: on these four independently implemented,
hand-authored loopback applications, the L8 engine change fixed a
measured single-resource blindness (two red-first tests, a DEV
re-measurement with recall 0.5 → 1.0, requests/TP 97.5 → 57.8, and
a fixed-baseline comparison that still misses the same defects);
benchmark scoring was corrected where it miscounted genuine
re-confirmations; held-out behavior, including a real false-
negative mechanism and the absence of any adaptive advantage over
the simple baseline there, is measured and reported without
adjustment.

What is NOT established: nothing in this document demonstrates
vulnerability discovery on any real-world application. The word
"generalization" appears nowhere as a claim; the only generalization
claim this project makes is the narrower, measured one: the engine's
probe coverage is resource-uniform by construction, which removed a
class of misses on apps built after the tuning corpus.
