    config_str = f"{self.base_url}|{self.organization}|{self.model}"
    return {
        "provider_type": self.provider_type,
        "mock_provider": self.is_mock,
        "provider_class": self.__class__.__name__,

        "base_url": self.base_url,

        "api_key_configured": bool(self.api_key),
        "api_key_prefix": self.api_key[:4] + "..." if self.api_key else "",
        "config_hash": hashlib.sha256(config_str.encode()).hexdigest(),
        "prompt_version_hash": self.prompt_version_hash,
    }

## Phase 5-6 — Differential Capability Benchmark (60 cases)

### Task 5.1: Design and implement DifferentialBenchmark-v1

**File to create:** `benchmarks/differential_v1/differential_target.py`
**File to create:** `benchmarks/differential_v1/manifest.json`
**File to create:** `benchmarks/differential_v1/ground_truth.json` (INDEPENDENT — runtime never receives)

**Partition design:**

#### Family A: Easy cases (20) — deterministic pattern matching should catch
- Direct IDOR: `/api/users/{id}/profile` where `{id}` is the path parameter
- Direct BAC: `/api/orders/{id}` with `X-Actor` header
- Simple ownership: `resource_owner != actor_echo` pattern
- Missing auth header on protected endpoint
- Method-based bypass: GET works but POST denied, but endpoint accepts GET for state change

#### Family B: Reasoning-heavy cases (20) — deterministic may miss
1. **Multi-step dependency:** Endpoint A grants token, Endpoint B requires token from A. Control doesn't mirror this chain.
2. **Hidden prerequisite:** Resource accessible only after workflow step X completes. CausalGuard sees same prefix but misses state requirement.
3. **Relationship-derived authorization:** User can access resource only if they share a group membership. Relationship derived from different endpoint.
4. **Delayed consequence:** Write endpoint returns 200 immediately, but side effect makes different endpoint vulnerable.
5. **Cross-resource invariant:** Setting field X on resource A changes behavior of resource B.
6. **Equivalent representations:** `/api/item/{id}` and `/api/items?id={id}` return same data but different authorization.
7. **Nested business workflow:** 3-level approval chain — skipping level 2 still works due to bug.
8. **Indirect object relationship:** User owns Group, Group owns Resource — user can access Resource via transitive ownership that CausalGuard doesn't trace.
9. **State-dependent permission:** Resource accessible only when `status=draft`, not when `status=published`.
10. **Counter-based authorization:** After N accesses, further accesses should be denied but aren't.

#### Family C: Novel composition cases (20) — never seen before in benchmarks
- Combinations of patterns from Family B that create novel attack surfaces
- Examples: state-dependent + relationship-derived, delayed + multi-step, etc.

**Implementation pattern for target server:**
```python
# Each case has: baseline route, candidate route, control route
# Routes designed so that CausalGuard's path-analogous + semantic-diff + auth-mismatch
# pattern may or may not catch them depending on whether additional reasoning is needed
```

**Ground truth stored INDEPENDENTLY in `ground_truth.json`:**
```json
{
  "diff_001": {
    "expected_label": "vulnerable",
    "ground_truth_digest": "sha256(mechanism+family)",
    "case_family": "easy",
    "mechanism": "direct_idor",
    "difficulty": 1
  }
}
```

**Runtime receives ONLY manifest with routes — no labels, no mechanism, no difficulty.**
