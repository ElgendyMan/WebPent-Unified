# Red Team Plan — v86 The Dojo (docs/plans/2026-10-16-v86-red-team.md)

Date: 2026-10-16. Target: the Dojo (v86, `src/webpent/dojo/` 15 modules,
`cli/dojo.py`, `tests/dojo/` 26 files, baseline **3144 passed**).

Method: full adversarial read of every dojo module, every defect reproduced
with a failing test first, one root-cause fix per defect, suite re-run after
each task. Every fix honors the Dojo charter: L-3 ground truth, L-4
deterministic, L-5 measured, L-6 adversarial honesty, L-7 no silent drops.

## Confirmed defects (all reproduced failing-test-first)

| id | module | defect | severity |
|---|---|---|---|
| RT-01 | `engine.py`, `tournament.py` | `respond()` matches routes by path only — the `RouteSpec.method` field is never consulted, so a POST-only route (`/login` in 5 templates) answers GET. Every built-in agent hardcodes `DojoRequest("GET", ...)`, which is why the bug stayed invisible. | high |
| RT-02 | `practice_runner.py`, `sparring.py`, `counter_adapter.py` | `runner.run()` unconditionally stomps `lab.request_budget` with the scenario budget, and sparring/counter_adapter re-stomp AFTER `pattern.apply()` — `shrink_request_budget` and `rate_limit_lockout` never take effect in sparring; two of the 12 defense patterns are dead code. | high |
| RT-03 | `lab_generator.py` | Retention retires `sorted(instance_ids)` lexicographically, not by start order: with seeds started out of order the "oldest" lab retired is the wrong one (dict insertion order is the true FIFO). | medium |
| RT-04 | `trainer.py` | `save()`/`load()` drop `hints_used`: a trainee who burns a hint, saves, reloads gets the hint back free — hint economics (HINT_COST=10) can be bypassed by reload. | medium |
| RT-05 | `weakness_identifier.py` | `_skill_gap` requires `total_fp > 0`: a family failing 100% of runs with zero false-positive claims produces NO skill_gap, so the clearest gap never reaches the plan's focus phase (L-7 says nothing is dropped). | medium |
| RT-06 | `cli/dojo.py` | `practice_cmd` records only `scenario_id/score/success`; `skill`/`weaknesses`/`plan` rehydrate `PracticeResult` with `requests_used=0, false_positives=0, time_steps=0, budget=0` — ledger-based skill always gets the full efficiency bonus and can never see a false positive. Measured numbers differ from live runs (L-5/L-6). | high |
| RT-07 | `engine.py` | `burn(lab, -5)` INCREASES the budget (`max(0, budget - (-5))`). Negative counts must clamp to zero. | low |
| RT-08 | `engine.py` | `VulnPoint.requires_auth` is dead — never consulted anywhere; route auth is checked but a vuln point demanding auth is matched regardless. | low |
| RT-09 | `progress.py` | `record()` appends to `history.jsonl` with no cap while audit is capped at 1000 — unbounded ledger growth contradicts bounded Dojo state (L-2). | medium |
| RT-10 | `progress.py` | `trend()` does `e["score"]` arithmetic on any entry carrying a `score` key — a non-numeric value in the ledger crashes every CLI command that reads history (`skill`, `weaknesses`, `plan`, `progress`, `status`). | medium |

Design notes (recorded, deliberately not fixed this wave): `trend()`'s last
window may be smaller than the window size; `PracticeGenerator` silently
drops weaknesses whose family has no library scenarios; sparring blue score
is binary per round while red's is graded. All three are spec-visible and
documented in the module docstrings.

## Tasks

### Task 1: RT-07 + RT-08 — engine hardening (burn clamp, point auth)
Files: modify `src/webpent/dojo/engine.py`, `tests/dojo/test_u_dojo_25.py` (new).
1. Failing tests: `burn(lab, -5)` leaves budget unchanged; `burn(lab, -1, lab with 0 budget)` does not go below 0; a vuln point with `requires_auth="user"` is not hit by an unauthenticated request (response flags `ok`), and is hit with a valid token.
2. Implement: clamp `count = max(0, int(count))` in `burn()`; in `respond()`'s point loop, before matching, if `point.requires_auth != "none"` and the session token is not valid, skip the point.
3. Done when: new tests pass; existing 13 engine tests still pass.

### Task 2: RT-01 — the engine honors the HTTP method
Files: modify `src/webpent/dojo/engine.py`, `src/webpent/dojo/tournament.py`, `tests/dojo/test_u_dojo_25.py`.
1. Failing tests: `GET` on a POST-only route returns 405 with flag `method_not_allowed` (add the flag to `RESPONSE_FLAGS`); `POST /login` with the sqli signature hits `vuln_hit`; method match is case-insensitive (`"post"` vs `"POST"`).
2. Implement: route match on `(path, method.upper())`; if any route matches path but not method → `DojoResponse(405, "method not allowed", ("method_not_allowed",))`. In `tournament.py` all four agents plan with `route.get("method", "GET") or "GET"` instead of hardcoded `"GET"`.
3. Done when: new tests pass; full suite re-run — any test that pinned a GET-onto-POST-route success must be updated to the corrected method (each updated with its own justification recorded here).

### Task 3: RT-02 — defense budget patterns take effect
Files: modify `src/webpent/dojo/practice_runner.py`, `src/webpent/dojo/sparring.py`, `src/webpent/dojo/counter_adapter.py`, `tests/dojo/test_u_dojo_25.py`.
1. Failing test: a provided lab whose budget was shrunk by a pattern (e.g. budget 1) runs at that budget in `runner.run()` — the result's `budget`/behavior reflect the pattern; and `SparringMatch.run` with `shrink_request_budget` produces a round whose red used fewer requests than the scenario budget allows.
2. Implement: in `runner.run()`, set `lab.request_budget = int(scenario.request_budget)` ONLY when `lab is None` (fresh lab). In `sparring.run()` and `AdaptationChallenge.run()`, set the base budget BEFORE `pattern.apply(lab)` (start → set budget → apply → run).
3. Update the pinned test in `tests/dojo/test_u_dojo_15.py` ("run overrides lab budget") to the corrected semantics: a fresh lab gets the scenario budget; a provided lab keeps its own.
4. Done when: pattern budget effects are observable; suite green.

### Task 4: RT-03 — retention retires true FIFO order
Files: modify `src/webpent/dojo/lab_generator.py`, `tests/dojo/test_u_dojo_25.py`.
1. Failing test: start seeds in scrambled order (5,3,1,0,2,4 → 6 starts); the FIRST-started instance is the one retired, not the lexicographically smallest.
2. Implement: retire from `self._labs` in insertion order (drop the `sorted()`).
3. Done when: new test passes; `test_retention_retires_the_oldest_first` and `test_retention_keeps_only_five_instances` still pass.

### Task 5: RT-04 — trainer persists hint state
Files: modify `src/webpent/dojo/trainer.py`, `tests/dojo/test_u_dojo_25.py`.
1. Failing test: request a hint, `save()`, `load()` → the reloaded session's `hints_used` is 1, and requesting a hint serves hint index 1 (not a repeat of hint 0).
2. Implement: add `"hints_used": self.hints_used` to the saved state and restore it in `load()` (clamped to 0..len(hints)).
3. Done when: new test passes; the 14 trainer tests still pass.

### Task 6: RT-05 — pure honest failure is a skill gap
Files: modify `src/webpent/dojo/weakness_identifier.py`, `tests/dojo/test_u_dojo_17.py`, `tests/dojo/test_u_dojo_25.py`.
1. Failing test: a family with 5+ runs at 0% success and zero false positives yields a `skill_gap` weakness.
2. Implement: drop the `total_fp == 0` guard from `_skill_gap`; adjust the detail string when there are no FPs.
3. Update the pinned test in `test_u_dojo_17.py` ("no-fp skill-gap rejection") to the corrected rule: fp no longer required; keep asserting that a PASSING family is never flagged.
4. Done when: new test passes; suite green.

### Task 7: RT-06 — the ledger carries the full measured result
Files: modify `src/webpent/cli/dojo.py`, `tests/dojo/test_u_dojo_25.py`.
1. Failing test: run `practice` for an agent that incurs a false positive (naive), then `skill`: the rehydrated profile reflects fp>0 and requests/time from the ledger (assert the ledger entry contains `false_positives`, `requests_used`, `time_steps`, `budget` keys).
2. Implement: `practice_cmd` records `result.as_dict()` fields into the ledger entry; the three rehydration sites (`skill_cmd`, `weaknesses_cmd`, `plan_cmd`) read those keys with `.get()` defaults so old-format ledger entries still load.
3. Done when: new test passes; the 14 CLI tests still pass.

### Task 8: RT-09 + RT-10 — bounded, robust ledger
Files: modify `src/webpent/dojo/progress.py`, `tests/dojo/test_u_dojo_25.py`.
1. Failing tests: `MAX_HISTORY_LINES` constant exists (5000) and `record()` caps the history file at it; `trend()` over a history containing `{"score": "n/a"}` and numeric scores returns without raising.
2. Implement: cap `record()` via `_append_line(..., cap=MAX_HISTORY_LINES)`; in `trend()`, keep only entries whose `score` is an int/float.
3. Done when: new tests pass; `test_u_dojo_21.py` (13 progress tests) still passes.

### Task 9: full verification + package
1. Run the full suite fresh: expect 3144 + new tests, 0 failures.
2. Ruff clean on `src/webpent/dojo/`, `cli/dojo.py`, `tests/dojo/`.
3. Rebuild `webpent_v86_1_dojo_red_team_hardened.zip`, extract in a clean directory, re-run suite + ruff from the extraction.
4. Update CHANGELOG (0.10.1 red-team entry), README status line, traceability doc release-gate row with the new measured numbers.
