## 0. How to read this registry

- **Canonical ID** is the only ID used going forward in reports, commits, DRIFT_REGISTER entries, and CI.
- **Aliases** map every historical numbering system (Part 3 Fix-Plan 0–5, Part 2 Red-Team 0–4, Part 5 Action-Plan 0–12, Part 6 Architecture 0–8, Part 4 §15 renumbered table).
- **Status vocabulary** (capability-level, never merged into one label): `implemented` · `wired` · `tested` · `verified` · `benchmarked` · `production_ready`.
- **Work categories** are separated inside each phase: R = recovery/security, C = completion of existing capabilities, N = new capability development, S = strategic research, P = production readiness.
- Phase completion requires: every in-scope item has a disposition (fixed / mitigated / deferred-with-reason / blocked-with-dependency), its acceptance criteria are met or the gap is explicitly recorded, and the phase report updates this registry.
