# Critique — v74 delivered work + the suggestion-3 plan as pasted (2026-10-14)

## A. Critique of the delivered v74 (critique fixes C1-C7 + validator coverage engine)

A1 (honesty gap, moderate): the registry now reports ``status="tested"`` /
``evidence_mode="deterministic"`` for ``elasticsearch_snapshot_traversal`` and
``xslt_injection`` while neither has a live producer agent. The comment in
``registry.py`` explains it and the traceability matrix marks both rows
"partial", but a consumer reading only ``all_capabilities()`` sees a claim the
codebase cannot back end to end. The honest fix is to keep the validator status
(the dispatch path IS deterministic) while making the producer gap visible in
the same record, not only in prose docs.

A2 (dead-code risk): ``_OFFLINE_FIXTURE_VALIDATORS`` is now an empty dict kept
"so capability_for still fails closed". That is fine, but the failure-closed
path is only exercised for ``unknown`` classes in tests; no test pins the
``missing-validator`` outcome for a never-implemented class outside the plugin
test's ``unknown_future_class``. Acceptable, but the new discovery work must
not add any second silent-promotion path.

A3 (test-name drift): ``test_postp0_phase5_validators.py`` docstring and one
registry test were edited in place for the Phase 6 promotions; the file name
still says "phase5" while it now covers Phase 6 reality. Cosmetic; documented
in the module docstring instead of renaming (renaming would churn imports and
history for zero behavior gain).

A4 (canary constant duplication): the XSLT canary string is defined in
``postp0_checks.py`` and re-declared as a literal in
``test_validator_coverage_engine.py``. Tests SHOULD re-derive from the module
constant so a future canary change cannot silently break the differential
tests' meaning.

## B. Critique of the suggestion-3 plan as pasted

B1 (governance violation, critical): the plan says "اضف الجديد مباشرة لقائمة
الفحص" — mined endpoints/parameters would be executed directly. That bypasses
this project's core architecture: nothing in the hunt loop mints requests
outside the planner/executor gates, and every candidate must carry an origin,
an idempotency key, and convergence accounting. Discovery output must be
ADVISORY seeds merged through the same bounded re-hypothesis path, never a
side-channel execution list.

B2 (module fragmentation): 9 new modules across ``discovery/`` and
``creativity/`` packages for what are pure, deterministic, no-I/O functions.
Fragmentation adds import surface and test surface without benefit. Correct
shape for THIS codebase: one module (``hunt_discovery.py``) with clearly
sectioned functions, wired into the orchestrator at one learn-side seam and
one re-hypothesis seam.

B3 (unbounded self-feeding loop): "حلقة متكررة" that "يصنع قائمته بنفسه" has no
termination story. Every hunt must terminate via typed stop reasons; discovery
candidates must participate in convergence accounting — a round that minted
candidates but produced no new evidence must still move toward stop, or the
loop becomes an infinite treadmill.

B4 (absolute thresholds presented as fact): ">30% timing diff" and ">20% size
diff" with no sample-size requirements produce noise classifiers that fire on
two outliers. Every differential signal requires a minimum sample count and
repetition before it can be classified "strong".

B5 (hallucinated findings risk): the hybrid generator pairs recorded
"capabilities" into scenarios. If capabilities are read from unverified
observations or LLM output, the system invents attack narratives that never
existed. Capabilities must come from recorded, evidence-bearing observations
only, and a scenario is a hypothesis with a test plan — never a finding, never
a confirmation.

B6 (scope escape): route-variant inference proposes sibling paths
(`/api/admin/...`, version bumps). These must never leave the target origin —
same host, same scheme — and must be deduplicated against every action the
loop has already attempted (seen-action signatures), otherwise the loop
re-probes the same 404s forever.

B7 (narrative reporting): "سأفحص... ابتكرتها بناءً على ما وجدته" — reports must
state machine-verifiable counts and origins, not personified claims. The
report gains a structured ``discovery_summary`` separating planned work from
discovered candidates, with every number derived from the same records that
drive execution.

B8 (runtime constants presented as schedule): "22 ساعة فعليّة" is planning
theater for a deterministic code task. The implementation plan below maps each
capability onto the real codebase and its test gates instead.

## C. Fixes applied in this build

C1->B1: discovery is advisory-only; nothing executes outside the existing
gates (see hunt_discovery.py module docstring and orchestrator wiring).
C3->B3: discovery candidates enter the same convergence ledger; a
discovery-only round with no new evidence converges like any other.
C4->B4: every classifier threshold is paired with a minimum-sample rule.
C5->B5: hybrid scenarios derive only from evidence-backed capability records
and are emitted as hypotheses with ``origin="discovery-hybrid"``.
C6->B6: ``_same_origin`` guard + seen-signature dedup on every minted candidate.
C7->B7: ``discovery_summary`` in ``to_report_json`` is computed from the same
records, not from prose.
C8->A1: ``coverage_gap()`` gains a ``producer_gap`` field so the gap is
machine-readable (``True`` for the two producer-less classes), with tests.
C9->A4: tests import the canary from the module constant.
