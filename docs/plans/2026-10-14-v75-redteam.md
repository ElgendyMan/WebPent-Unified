# Red-team critique — v75 (adaptive discovery engine, suggestion 3)

Date: 2026-10-14. Target: everything added in the v75 build —
`src/webpent/autonomous/hunt_discovery.py`, the orchestrator wiring
(`_phase_discover`, `_merge_discovery_hypotheses`, `_merge_gap_hypotheses`),
`hunt_state.py` (`discovery`, `discovery_signatures`, `_discovery_summary`),
`registry.py` (`producer_gap`), `tests/test_autonomous_hunt_discovery.py`
(32 tests), the Task 10 docs, and the delivery process itself.

Method: line-by-line re-read of the shipped code against its own claimed
invariants (advisory-only, evidence-bounded, same-origin, convergent,
deterministic, redaction-safe), plus an adversarial read of the tests for
what they pin and what they never exercise. Nothing here was found by a
failing test suite — the suite is green. That is itself finding R0.

## R0 — the green suite proves less than it claims

2228 passing tests did not catch a single one of the correctness findings
below (R1, R2, R5, R6, R12, R14). The suite tests that thresholds fire when
given healthy inputs; it does not test degenerate inputs (tiny magnitudes,
deep records, host-like strings), and one test actively pins a bug as
correct behavior (R18a). Green was treated as evidence of correctness; it
is only evidence of the absence of the assertions I chose to write.

## Correctness defects in `hunt_discovery.py`

**R1 — `_stringify_strings` depth cap counts stack pops, not nesting
depth.** `depth` is incremented once per `while` iteration, so `depth > 6`
stops the walk after seven stack pops total, regardless of how deep the
current value is. A flat record with eight string fields loses everything
after the seventh; a nested record with two strings per level dies the same
way. The bounded-traversal claim in the docstring ("bounded") is true, but
the bound is not the one the code name implies, and no test exercises it.
Fix: track depth per nesting level (walk `(value, depth)` pairs), keep the
200-string cap, and pin both with tests.

**R2 — divergence has no absolute floor, so tiny magnitudes fire.**
`(high - low) / max(high, 1)` is relative to the larger value only. A 3-byte
response vs a 4-byte response is divergence 0.25 ≥ 0.20 → size anomaly. A
10 ms vs 20 ms response is divergence 0.5 ≥ 0.30 → timing anomaly. The
minimum-sample rule gates how many records, never how big the difference
actually is; on small-magnitude endpoints the engine manufactures anomalies
out of noise. Fix: pair each relative threshold with an absolute minimum
delta (bytes and milliseconds), which is exactly the same threshold-paired-
with-floor discipline the module applies to sample counts.

**R3 — `status_divergence` confidence is a hardcoded 0.8** regardless of
how many distinct statuses were seen or how many samples backed them. Two
statuses and five statuses produce identical confidence; the number carries
no information. Fix: derive confidence from the distinct-status count,
keeping the value at the strong gate for the minimum case so existing tier
behavior is preserved.

**R5 — the `/api/v2` route variant doubles the `/api` prefix.**
`"/api/v2" + template` where `template` already starts with `/api/` mints
`/api/v2/api/items/{id}`. Worse, `test_route_variants_are_minted_for_id_templates`
asserts this garbage path is present — the test pins the bug. Fix the
variant math (strip the observed `/api` prefix before prepending the
versioned one) and fix the test to pin the corrected behavior.

**R5b — the un-generalized template is minted as a "route candidate".**
For a template not starting with `/api/`, the middle tuple element is the
template itself (`/items/{id}`): a placeholder path with `{id}` in it, which
no executor can request, passing the `variant == source` filter because
`source` is the concrete recorded path. Candidates containing `{id}` must
never be minted.

**R6 — the `/admin` prefix variant is minted unconditionally.** Every
`{id}` template gets an `/admin/...` sibling even when nothing in the
observed records ever mentioned an admin surface. This is speculation, not
evidence-bounded inference, and it contradicts the module's own
"EVIDENCE-BOUNDED" claim. Fix: gate the admin variant on observed evidence
(the string `admin` appearing in the round's records or the template itself).

**R12 — endpoint mining mints hostname fragments and has no origin
discipline.** `_PATH_TOKEN` applied to a record's own `url` field
(`https://lab.example/api/items/177`) yields `/lab.example`, `/177`, and
other garbage — all minted as "endpoint" candidates. The filter
`":" in match.split("/")[0]` only catches colons inside the match; the
`://` split leaves the host as its own token. There is also no same-origin
check anywhere in `mine_endpoints`, while the traceability matrix row claims
"same-origin route/parameter/endpoint candidates". The docstring's
same-origin sentence covers routes/params only. Fix: use match positions to
skip tokens whose preceding characters are `:` or `/` (URL-context
fragments), and correct the traceability wording.

**R14 — uncertainty budget semantics are inverted.** The
"observed-paths"/`documented` region's `unexplained_anomalies` is computed
as the count of `noise`-tier anomalies. Noise anomalies are the ones the
classifier already explained away; counting them as unexplained inflates
the documented region's budget. Fix: only `interesting`/`strong` count as
unexplained, attributed to the anomalous region; the documented region
carries none.

**R11 — parameter signatures key on the sibling name alone.**
`_seen_signature("param", sibling)`: once `uid` is minted from an observed
`id` anywhere, an observed `user_id` on a completely different endpoint can
never mint `uid` again. Parameter candidates are endpoint-scoped; their
dedup key must be (source, sibling). Route keys (variant path) are
correctly global.

**R8b — hybrid scenarios are never deduped across rounds.** Routes,
endpoints and params are remembered in `state.discovery_signatures`; hybrids
are not. A capability pair that stays present re-mints the identical
scenario every round forever. Fix: remember the hybrid signature too.

**R9 — the repetition model is "consecutive rounds only" and undocumented.**
`_phase_discover` passes only the previous round's classified anomalies as
`history`. A signal present in rounds 1 and 3 but absent in round 2 never
reaches `strong`, because round 3's history (round 2) does not contain it.
That may be the right strictness, but it is nowhere stated, and no test
covers the skip-round case. Fix: document the semantics in the docstring
and pin them with a test.

**R21 — `classify_anomalies` counts history entries regardless of tier.**
Correct today only incidentally: noise-tier entries have confidence < 0.5,
so they can never satisfy the strong gate. The invariant "history noise
cannot become strong" is accidental, not enforced. Document it or filter
the history to interesting/strong explicitly.

## Wiring and state defects

**R7 — routes, endpoints and params are minted, counted, reported… and
consumed by nothing.** The orchestrator harvests their signatures for dedup
and counts them in the agenda and the report, but no code path ever turns a
route/endpoint/param candidate into a hypothesis seed or a task. The engine
advertises inventory the loop cannot act on. This is the single largest
honesty gap in v75: the module docstring implies the loop "builds its own
checklist"; in fact only the strong-anomaly seeds do anything. Fix: an
explicit, documented non-claim (candidates are advisory inventory for the
operator and future consumers, not executable), stated in the module
docstring, the plan record, and the traceability row — plus hybrids joining
the signature memory so repeated rounds stop re-minting them.

**R10 — merged discovery seeds render with a blank `pattern_id` in the
report.** `to_report_json`'s hypothesis projection reads
`pattern_id or id`, but discovery seeds carry `hypothesis_id`/`gap_id`. The
report's `hypothesis_origins` will show `discovery-anomaly` entries whose
pattern_id is an empty string. Fix: extend the fallback chain.

**R17 — seed target pinning discards the actionable payload.**
`_merge_discovery_hypotheses` pins `target_url` to the hunt's generic
target even when the anomaly's `probe` is itself a same-origin URL of the
divergent endpoint. The planner receives a hypothesis that cannot point at
the thing that diverged. Fix: when the probe parses to the hunt's own
origin, use it as the seed's `target_url`; keep the generic pin otherwise.

**R16 — discovery phase records are indistinguishable from observation
records.** `_phase_discover` records under `HuntPhase.OBSERVE` with
`status="ok"` and `reason=""` on the productive path. A phase-trace reader
cannot tell a discovery round from an observation record without parsing
the detail dict. Fix: set a stable `reason` (`"discovery_candidates"`) on
the ok path.

**R26 — magic numbers in the orchestrator.** The per-round seed cap `8` and
the repeated `[:160]` truncations are unnamed literals; the engine module
names every cap (`_MAX_HYPOTHESIS` etc.) while the orchestrator hardcodes
its own. Fix: named constants.

**R23 — the pipeline takes the first record's URL as THE origin.**
Multi-origin record sets (redirect notes from a foreign host) get their
routes checked against the wrong origin. Single-target hunts make this
benign today, but the function signature accepts anything. Fix: document,
and prefer the origin that matches the most records (still deterministic).

## Report and redaction-safety

**R31 — mixed semantics inside `discovery_summary`.** `anomalies` …
`hybrid_scenarios` are current-round counts; `minted_candidate_signatures`
is an all-rounds count; they sit side by side with no naming distinction.
Fix: rename the cumulative field or split the block; pin with a test.

**R20/R31b — the redaction contract is convention, not enforcement.**
`_discovery_summary` copies the `agenda` dict wholesale. Safe today because
the agenda is counts and static strings; one added field in
`build_discovery_agenda` silently enters the report unaudited. Fix: assert
the agenda's shape in a test, and keep the summary counts-only.

## Test-suite defects

**R18a — the doubled-`/api` test pins the bug** (see R5). A test whose
assertion encodes wrong behavior is worse than no test.

**R18b — untested surfaces:** `_stringify_strings` depth/caps (R1), absolute
floors (R2), skip-round repetition (R9), admin gating (R6), endpoint
host-fragment filtering (R12), budget semantics (R14), param signature
scope (R11), hybrid dedup (R8b), report `pattern_id` fallback (R10), seed
target propagation (R17). Ten behaviors shipped with zero assertions.

**R18c — `_XSLT_CANARY` is a private name imported across modules** in
`test_validator_coverage_engine.py`. It was the right call for consistency,
but the contract is fragile: renaming the constant breaks a test suite that
otherwise has no business knowing it. Acceptable; document as accepted
fragility.

## Documentation defects

**R19 — the traceability row overclaims.** "same-origin route/parameter/
endpoint candidates with seen-signature dedup and caps" — endpoint mining
has no origin check (R12), and route/param/endpoint candidates have no
consumer (R7). The row reads as more capability than exists. Fix: reword to
what is real.

**R24 — the module docstring's EVIDENCE-BOUNDED/SAME-ORIGIN claims** are
each contradicted by one function (R6, R12). Docs must either match the
code or the code must match the docs; here neither matches fully.

## Process defects

**R25a — the inventory regen was miscounted once** (`unapproved_raw_transport`
22 vs 20, caught and corrected). The correction was right; the mistake
happened because the regeneration script was written inline rather than
reused from a checked path.

**R25b — a known-wrong behavior was pinned instead of fixed.** The doubled
`/api` variant was noticed during implementation and pinned by a test
"so it is at least deliberate". Deliberate wrongness is still wrongness.

**R25c — the Playwright `PLAYWRIGHT_BROWSERS_PATH` workaround is
session-local** (symlink at `/home/thaura/pw-browsers`). It is documented in
the plan record, which is correct, but a fresh environment hits the same
wall with no repo-level note. Accepted environment limitation; keep it
documented.
