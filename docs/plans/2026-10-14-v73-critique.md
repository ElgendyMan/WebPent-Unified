# Self-critique of the v73 delivery (2026-10-14)

Directive: critique all delivered work, fix every critique and problem that
emerges, then execute suggestion 2 (validator coverage engine) in full.
Every critique below was verified against the code, not assumed.

## C1 (critical): suggestion 1 is ineffective against the real controller

The gap-driven re-hypothesis loop (Task 8) never fires in the wired hunt, for
two independent reasons.

**C1a — the real controller never emits `knowledge_gaps`.** The orchestrator's
`_phase_observe` reads `update.get("knowledge_gaps")` from the controller's
return value, but `AutonomousController.run()` builds its update from exactly
these keys: `campaign_task_outcomes`, `lifecycle_events`, `recovery_events`,
`coverage_ledger`, `causal_attack_edges`, `causal_edges`, `attack_graph`
(src/webpent/shared/autonomous_controller.py, result-assembly block). There is
no `knowledge_gaps` key, so `state.knowledge_gaps` stays empty for the whole
hunt and `_phase_rehypothesize` returns 0 on every quiet iteration. The real
gap data exists one key over, in `coverage_ledger`.

**C1b — the synthesizer cannot read the gap records that do exist.**
`synthesize_gap_hypotheses` extracts `gap_id`, `description`, `severity`,
`required_evidence`, `resolved`. The controller's real coverage-gap records
carry `{key, status, attempts, evidence_complete, proof_action_id, task_id,
reason, gaps[]}` (coverage_ledger entries as projected by
`CoverageIntelligence.project()`). None of the five expected fields exist, so
every real record is silently skipped as "not coercible". The feature worked
only against the synthetic `_gap()` fixtures in its own test file.

Net effect: Task 8 was tested green and shipped, but in production the loop
it was built to close remains closed by exactly the failure it was meant to
fix. Root cause of the miss: the tests fed the synthesizer the same synthetic
shape the synthesizer was written for. The test suite and the implementation
shared a fiction. (Fixed in this pass; see "Fixes".)

## C2 (moderate): `CoverageIntelligence.gaps()` undercounts missing-validator

`_project_coverage_ledger` deliberately preserves the `missing-validator`
status (it is exempted from the `not_scanned` fallback) and appends the
`deterministic-validator-unavailable` gap string for it. But `gaps()` selects
only six statuses and omits `missing-validator` — so the exact classes this
pass is about (the parked validator classes) do not appear in the gap list
that the coverage engine reads. Fixed.

## C3 (moderate): an earlier claim about validator scope was wrong

Earlier notes described the missing-validator set as "SSTI/XXE/SSRF/…". That
is false: those classes (and 27 others) all have live deterministic
validators. The true offline-fixture set is exactly three classes:
`cloud_storage_exposure`, `elasticsearch_snapshot_traversal`,
`xslt_injection`. Worse, only one of the three (`cloud_storage_exposure`) has
a live producer agent; the other two exist only in the campaign inventory, the
capability registry, and the explicit WAPTLab benchmark fixture profile. A
live validator for a class with no producer cannot confirm anything today; it
can only make the dispatch path honest (deterministic re-probe instead of a
generic "validator unavailable" dead end) and close the registry gap so any
future producer lands on a real validator. That is still worth doing, and is
done here, but the docs must not claim "full live coverage of the three
classes" — they get live validators and a producer gap for two of them.

## C4 (moderate): no regression test fed a real-shaped gap record

Consequence of C1: the replanning tests only exercised the synthetic shape. A
test that feeds the controller's actual coverage-ledger record shape would
have gone red immediately. Fixed: new tests feed both real shapes and a fake
controller that emits `coverage_ledger` (the real key) instead of
`knowledge_gaps`.

## C5 (minor): redaction test exclusion set is a whitelist-of-convenience

The "401" false positive was fixed by excluding `detail_digest` and
`at_monotonic` from a whole-payload plaintext check. The root cause is that
the check ran over non-string fields at all: a numeric uptime timestamp can
coincidentally contain any digit sequence ("1053.283401" contains "401").
The principled fix is to redaction-check only string leaves. Fixed.

## C6 (minor): phase-trace noise guard tested only the empty-list case

The `_phase_rehypothesize` early return fires when `state.knowledge_gaps` is
empty, but after fix C1a the list can also be non-empty with zero new seeds
(dedup) — that path records an "empty" phase entry on every quiet iteration
and can still flood the trace. Verified bounded (`_MAX_RECORDS` = 256) but
now covered explicitly by a test.

## C7 (minor): hunt-state report omits knowledge-gap provenance

`to_report_json()` reports hypothesis pattern/priority but not which
hypotheses originated from knowledge gaps, so an operator reading the report
cannot see that re-hypothesis happened or from which gap classes. Fixed:
report now includes `origin` counts.

## Suggestion 2 — validator coverage engine (executed)

New live deterministic validators for the three offline-fixture classes, in
`postp0_checks.py` (the established home for parked-class promotions):

1. `validate_cloud_storage_exposure` — fresh GET of the bucket URL; confirm
   requires provider listing markers on the candidate AND their absence on a
   random-object-path negative control on the same host. Marker-free candidate
   is an explicit negative; transport failure is inconclusive.
2. `validate_elasticsearch_snapshot_traversal` — fresh GET of the snapshot
   endpoint; confirm requires repository/snapshot JSON markers AND a
   marker-free ES error response on a nonexistent-handler negative control.
3. `validate_xslt_injection` — replay of the finding's request with a benign
   stylesheet canary (`xsl:value-of` of a fixed literal); confirm requires the
   canary in the candidate response AND its absence under an inert-value
   control. Findings without a replayable request template fail closed to
   inconclusive — never guessed.

All three route through `_evidence` + `_confirmed` (strict replay verifier:
target-backed observations, independent negative control, provenance, sealed
bundle). Registry: all three move from `_OFFLINE_FIXTURE_VALIDATORS` to
`_IMPLEMENTED_VALIDATORS`; dispatch in `agent.py` routes them; campaigns.py
drops them from `CAMPAIGN_HUMAN_REVIEW`.
